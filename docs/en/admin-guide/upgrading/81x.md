# Upgrading to GROWI v8.1.x

GROWI v8.1 reads environment variables strictly. Invalid values used to be silently coerced or replaced, but from v8.1 they stop startup by default. If you host GROWI yourself, check your environment variable values before upgrading.

### [Action Required] Strict checking of environment variable values

GROWI v8.1 checks each environment variable against the type defined for its setting (number, boolean or JSON). This check (strict mode) is enabled by default. If even one environment variable has an invalid value, GROWI stops at startup.

The accepted values for each type are:

| Type | Accepted values | Examples of rejected values |
| :--- | :--- | :--- |
| Number | Plain decimal notation only (e.g. `4`, `0.5`) | `0x1F`, `1e3`, `12abc`, `-1`, `+1`, `Infinity`, values with leading or trailing spaces |
| Boolean | `true` / `false` / `1` / `0` (case-insensitive) | `yes`, `on` |
| JSON | Valid JSON | Values with syntax errors |

An empty value for a number, boolean or JSON variable counts as unset, so the default value applies. String variables still accept an empty value as is.

When a value is invalid, an error like the following is output at startup. It lists every environment variable with an invalid value, but never prints the values themselves.

```text
Invalid environment variable value(s):
  - MAX_FILE_SIZE: expected a decimal number such as 4 or 0.5
Fix the value(s), or set CHECK_CONFIGURATION_VALUE_STRICTLY=false to fall back to the default values.
```

::: warning
Previous versions of the [Environment Variables](/en/admin-guide/admin-cookbook/env-vars.html) page listed `Infinity` as the default for `MAX_FILE_SIZE` and `FILE_UPLOAD_TOTAL_LIMIT`. However, setting either variable to `Infinity` is treated as an invalid value. If you do not want a limit, leave these variables unset.
:::

`AI_PROVIDERS`, `AI_PROVIDER_API_KEYS` and `AI_ALLOWED_MODELS`, which configure the AI integration, are checked like any other environment variable. A value that cannot be parsed as JSON (for example, because of an escaping mistake) used to produce only a warning, but from v8.1 it stops startup. A value that is valid JSON but has an unexpected shape is handled as before: a warning is logged and the setting is treated as not configured.

If you see the error, do one of the following:

- **Fix the values (recommended)**: Change each listed environment variable to a value that matches its type, as shown above.
- **Disable strict mode**: Set the environment variable `CHECK_CONFIGURATION_VALUE_STRICTLY` to `false`. Invalid values are then replaced with their defaults, a warning is logged, and GROWI continues to start.

If `CHECK_CONFIGURATION_VALUE_STRICTLY` itself has an invalid value (such as `ture`), strict mode stays enabled and the variable is included in the error list. For details, see [Environment Variables](/en/admin-guide/admin-cookbook/env-vars.html).

### [Specification Change] Numeric environment variables are no longer partially parsed

Numeric environment variables used to be read only as far as the leading part could be parsed, so part of an invalid value could still be used as a number. From v8.1, a value is accepted only if the whole value is valid.

| Value | v8.0.x and earlier | v8.1.x and later |
| :--- | :--- | :--- |
| `12abc` | `12` | Invalid |
| `0.5` | `0` (fraction truncated) | `0.5` |
| Malformed JSON | `null` | Invalid |

In strict mode, an invalid value stops startup. With strict mode disabled (`CHECK_CONFIGURATION_VALUE_STRICTLY=false`), the default value is used instead.

If you set a decimal value for a numeric environment variable, its fractional part now takes effect from v8.1. Check that the resulting value is what you intend.

</ContextualBlock>


## Things to Check Before Upgrading

<ContextualBlock context="docs-growi-org">

- [x] Do any environment variables have values that do not match their type? (e.g. `MAX_FILE_SIZE=Infinity`, booleans such as `yes`/`on`, malformed JSON)
- [x] Do you set `TRUST_PROXY_HOPS` or `TRUST_PROXY_BOOL`? (If so, check the recorded client IP addresses after upgrading.)
- [x] Do you set a decimal value for any numeric environment variable? (v8.0.x and earlier truncated the fractional part.)

</ContextualBlock>
